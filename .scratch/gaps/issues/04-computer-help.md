# 04: 电脑求助

**What to build:** bot 卡在验证码、登录这类需要人的地方时，调用 `computer_request_help`，主人看到求助，接管处理，归还后 bot 自己接着做。

**Blocked by:** 无

**Status:** done

- [x] 新工具 `computer_request_help({reason})`，只有本回合持有电脑租约的 Run 能调；空原因拒绝
- [x] 求助记在电脑控制状态里，落盘，`status().help` 带出来；发 `computer_help_requested` 事件
- [x] 归还成功后自动开一次继续的 Run（source `computer_help`），先截图核对再接着做；每次求助只叫一次
- [x] 关机等于放弃求助，之后归还不叫 bot
- [x] 电脑面板出现"助手请你帮忙"提示；接管期间桌面画面每秒刷新，平时 3 秒
- [x] `test/computer-help.mjs` 7/7；四个变异（不清求助、归还不叫、关机不清、不查租约）都抓到

## Comments

改了路线。原计划让 Run 原地进入等待态，等主人处理完再继续。现有安全模型是接管让代号 +1，旧回合的租约永久作废，旧动作一律拒绝。原地等待就要让旧租约复活，等于拆掉这道门。

现在的做法不碰这道门。求助的回合说一句要主人做什么就结束；归还时用新租约开一个新 Run。同一个 bot 常驻会话，新 Run 记得上下文。

接管期间加快截图只在前端做，后端截图接口不变。真正的视频流（VNC）不做，成本高，1 秒一帧够处理验证码和登录。
