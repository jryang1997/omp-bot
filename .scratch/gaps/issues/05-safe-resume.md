# 05: 中断 Run 的安全续跑

**What to build:** 服务重启中断的任务，用户点一下"接着做"就续上。续之前先让 bot 核对上次做到哪，做完的不重做。

**Blocked by:** 无

**Status:** done

- [x] `POST /api/runs/:id/resume`，只有主人能调
- [x] 只续 `interrupted`。有在飞外部动作的是 `reconciliation_required`，不能续，要人核对
- [x] 幂等：旧 Run 记 `resumedBy`，新 Run 记 `resumeOf`；重复点只拿回已有那次
- [x] 群聊回合、派出去的子任务不续（返回 409 `resume_unsupported`），它们的交回链路续不上
- [x] 任务详情里中断的任务出现"接着做"按钮
- [x] `test/resume.mjs` 5/5；去掉幂等判断、去掉状态判断两个变异都抓到

## Comments

改了路线。原计划是重启时自动续跑一次。现有设计明确写着"重启后未完成的事件不会自动重放，需要人工确认"，自动续会推翻这个约定，用户也会被突然开跑的任务吓到。改成用户点按钮。

不需要 OMP `--continue`。每个 bot 一个常驻原生会话，新 Run 本来就接着同一会话，上一回合的历史都在。只要在新消息里说清"先核对再接着做"。

和已有的"重试"不同：重试是原样再发一次，可能重做已经做过的事；接着做会先核对，并且只能续一次。
