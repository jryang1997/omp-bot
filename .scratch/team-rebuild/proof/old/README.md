# 10 旧电脑的文件搬进共享电脑的证据

- `old-e2e.mjs`：沙盒里真跑两个脚本。旧电脑里的打包脚本（`src/computer-seats.mjs` 的 `OLD_EXPORT`）以一个普通用户运行，替旧电脑里的 cua；`guest/omp-seat import-old` 以 root 运行，解进一个真的座席用户。结果在 `old-e2e.json`（4/4）。
  - 打包：/work 和主目录进包，root 才能读的文件跳过（不让整个打包失败），`.cache` 和浏览器 profile 不带
  - 解包：文件全归座席用户，`~/old-computer` 是 0700，别的用户读不到；座席里已有的文件不覆盖；中文和空格文件名、指向外面的链接原样；包解完就删，收件目录 `/var/tmp/omp-old` 是 root 0700
  - 重复解包不覆盖座席里改过的文件
  - 拒绝：包不在收件目录、路径带 `..`、用户不存在、不是座席用户、`~/old-computer` 是符号链接
- `shot-old-panel.mjs`：面板。后端用替身，HTTP 接口和前端是真的。结果在 `panel-report.json`（8/8），截图 `panel-old-error.png`、`panel-old-done.png`。
  - 出错时写明哪一步错了，有「重试复制」；复制中显示步骤，没有删除按钮；轮询到完成后显示文件数和时间
  - 删除前确认，取消不删；没复制完的旧电脑确认框里提醒文件还没复制；助手已删的旧电脑也列出来；都删完这一行隐藏
- 座席层的编排（开旧电脑、打包、取回、关旧电脑、开座席、上传、解包、关座席，一台一台来，出错不挡后面的，做完跳过，出错要重试，复制中不删）在 `test/seats.mjs` 的三项 10 号测试里，用替身后端。

途中修掉的：座席里原来就有 `~/old-computer/work` 时，`mkdir -m 0700` 不改已有目录的权限。改成建完以后 `chmod 0700 ~/old-computer`。

没覆盖的：真实旧电脑（QEMU 里的 Debian、cua 用户、spacesd 下载大文件）和真实共享电脑之间的整条链路。要在有 KVM 或 WHPX、留着旧电脑磁盘的机器上跑一次。
