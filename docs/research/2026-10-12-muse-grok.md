# 竞品研究报告：Meta Muse 与 xAI Grok Bot（截至 2026-10-12）

> 范围：只研究 **Meta Muse（个人 agent 产品）** 与 **xAI Grok Bot（常驻 agent 产品）**，并把二者各自与「Muse Spark 模型」「普通 Grok 聊天」严格区分。
> 方法：以官方一手来源为主（产品站、官方文档、官方 Help Center、官方博客、隐私/安全政策）。二手来源仅作线索，凡未经一手来源确认者显式标注。
> 本文件仅供调研，不含实现。所有 URL 为 2026-10-12 抓取的原文地址。

---

## 0. 结论速览

| 维度 | Meta Muse | xAI Grok Bot |
|---|---|---|
| 产品形态 | 个人 AI agent：聊天 + 后台任务 + 云 VM + 手机/Mac/眼镜 | 团队型常驻 agent：每个账号一台云电脑 + 多个命名 Bot |
| 云端运行时 | 每用户独立 VM（Muse Secure VM） | 每用户一台共享云电脑（Firecracker microVM）；所有 Bot 共用 |
| 本地运行时 | Mac app 有完整 computer use（Full Disk Access/Automation）；Windows/Linux 仅浏览器 | 桌面 app 可本地执行命令（默认逐条审批）；云电脑是主战场 |
| 常驻/主动性 | 后台任务、提醒、定时任务、目标追踪、AI 打电话 | routine 定时/事件触发，电脑关着也在跑；@bot 来自 X |
| 多智能体 | 官方博客称会「launches swarms of subagents」；UI 层未见命名 Bot 花名册 | 一等公民：命名 Bot、私信互发、群聊（2–6 Bot）、任务移交 |
| 连接器/OAuth | Connectors + 自建 Custom Connector | 连接器即插件；OAuth token 存在 Cursor 后端，Bot 看不到 |
| 记忆 | 文件系统式 MEMORY.md / Soul.md / Identity.md，可编辑、可 forget、可导入外部 AI 历史 | 每 Bot 独立记忆 + 共享电脑文件/浏览器会话；Bot 描述承载长期规则 |
| 权限/自治边界 | Sentinel 独立权限权威；Allow once / task / site / always / Deny；读写分权 | Auto Review 独立审查模型 + 逐动作审批；本地执行策略 |
| 计费 | 免费额度 + Power $20/月（500M tokens/周）/ Max $100/月（3B tokens/周） | 不单独售卖，随 Cursor 付费计划或 SuperGrok 赠送；周度额度 + 按需超额 |
| 区域 | 有限测试，并非所有地区可用 | 美/加等主流地区；@bot 打标在 AU/UK/EU/冰岛/列支敦士登/挪威不可用 |

## 1. 产品身份辨析（必须先分清）

### 1.1 Meta 侧
- **Muse** = Meta 的「个人 AI agent」消费产品，2026-09-08 发布（研究博客发布时间戳 2026-09-08：https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse ）。入口：App（iOS/Android）、Mac app、网页 muse.ai、WhatsApp、即将上 AI 眼镜与 Muse Charm 硬件（https://www.meta.com/blog/meta-connect-2026-everything-we-announced/ ）。
- **Muse Spark / Muse Spark 1.3** = 驱动 Muse 的**前沿模型**，不是产品。同一系列还有 **Muse Code**（终端/CI 编码 agent，多智能体）、**Muse Image**、**Muse Voice Transcribe**、**Muse Glimmer**（30B 开源权重，可单 GPU/Mac Mini 本地跑）（https://developers.meta.com/blog/meta-connect-recap/ ；https://dev.meta.ai/models/muse-spark/ ）。
- 安全博客原文把两者写在一起：「Muse Spark 1.3 is close to SOTA on this capability」（指抗提示注入），可见 Spark 是模型层（https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse ）。
- **不要**把 `muse.ai` 与 `ai.meta.com/muse` 之外的第三方同名站点（Tracxn 上名为 MetaMuse 的营销公司、museandmetta 等）当成本产品。

### 1.2 xAI 侧
- **Grok** = 对话式助手（chatbot），见 https://docs.x.ai/grok/overview 。
- **Grok Bot** = 「AI teammates」常驻 agent 平台，2026-08-11 早期 beta 发布（https://x.ai/news/introducing-grok-bot ）。官方文档专列常见问题「How is Grok Bot different from the Grok chatbot?」：Grok 是对话，Grok Bot 是针对目标持续工作的 agent（https://grok-bots.com/ ，第三方站，引自官方 FAQ）。
- **归属**：Grok Bot 文档与计费均落在 **Cursor / Anysphere** 体系（`docs.x.ai/grok-bot/*`、`cursor.com/help/grok-bot/plans`、Cursor dashboard）。Grok Bot 的云电脑「run in Cursor's cloud」（https://docs.x.ai/grok-bot/overview ）。因此**Grok Bot ≠ 普通 Grok 订阅**：它有独立额度，不占用 Grok 聊天额度（https://x.ai/news/introducing-grok-bot ）。
- 长尾细节（SuperGrok Heavy $300/月、Cursor Ultra $200/月等具体价）来自第三方 grok-bots.com；官方只有「随 Cursor 计划或 SuperGrok 链接赠送、周度额度」的口径（见 §5）。该价目**标为二手/待官方确认**。

## 2. Meta Muse：能力清单（15+，附一手证据）

1. **聊天非回合制**：官方 Help 明确「Unlike other AI apps, Muse is not turn-by-turn」，可连续追问不重复上下文；另有 Side chats 分主题且跨主/侧聊天保持知觉（https://www.meta.com/help/artificial-intelligence/1331373868832401/ ）。
2. **云 VM 运行时**：Muse 跑在云端 "virtual machine" 里，保存你共享的信息与共同产物，每用户 VM 隔离；核心客户端（iOS/Android app、web UI）直连该 VM（https://muse.ai/privacy ；https://www.meta.com/help/artificial-intelligence/1047255454427887/ ）。
3. **任务执行（agentic）**：给目标后自行判断需要哪些内置 skill，跨步骤浏览网页、取连接器数据并行动；你通过权限与逐步审批保持控制（官网 FAQ，https://ai.meta.com/muse/ ）。
4. **后台常驻**：关掉 app 仍继续工作，例如「监控每日天气并提醒带伞」（https://ai.meta.com/muse/ FAQ；https://www.meta.com/help/artificial-intelligence/1331373868832401/ ）。
5. **提醒/定时任务**：一次性、按位置触发（"next at the store"）、按日/周/自定义间隔的 recurrence，可在 Upcoming 查看/取消/改时间（https://www.meta.com/help/artificial-intelligence/1484325780075655/ ）。
6. **目标追踪（Goals）**：可设个人目标，Muse 追踪进度并主动 check-in（https://www.meta.com/help/artificial-intelligence/2225571704857152/ ）。
7. **内置 Skills**：由 Meta 开发、已内置于 Muse（播客、生图、调研、文档、dashboard、浏览网页等），**不需要安装**；按请求自动激活（https://www.meta.com/help/artificial-intelligence/2797651547267109 ）。
8. **Artifacts/文件**：读/建/编辑/总结 PDF、DOCX、文本、MD、XLSX、CSV、图片、代码、可交互单页 web 应用；产物存 Library，可删（https://www.meta.com/help/artificial-intelligence/2074655449783957/ ）。
9. **云浏览器**：chat 内可被你和 Muse 共同控制的浏览器，可预约、代购、填表、盯价格；可 Open browser 观察、Take control 暂停、Stop the task 终止；可让 Muse 列出访问过的 URL 与接受的 cookie（https://www.meta.com/help/artificial-intelligence/2124746764949121/ ）。
10. **Mac 本地 computer use**：对本地文件与应用（iMessage、Notes、Reminders、Mail、Calendar）操作；权限由 macOS 控制：Full Disk Access、Automation、Notifications；每个本地 app 可选 Off / Read only / Read and interact；删除文件先入废纸篓（https://www.meta.com/help/artificial-intelligence/1126304576638594/ ）。
11. **Connectors**：Meta 与第三方连接器，Facebook/Instagram/Threads 若同一 Accounts Center 自动连接；可自定义 Custom Connector（Meta 不审核，需自行判断风险）；可随时断开，但历史可能残留（https://www.meta.com/help/artificial-intelligence/1687253048996149/ ）。
12. **凭证安全**：凭据存入 Secure Credentials Store，模型看不到密码；使用前有「目标服务/是否授权/是否允许该动作」三重检查（https://www.meta.com/help/artificial-intelligence/1047255454427887/ ）。
13. **支付**：购买**总是**先审批；推荐 Link by Stripe（一次性卡号，含退换/降价等保障）；也支持用保存的信用卡登录后购买；购买能力受地区/商户/结账流程限制（https://www.meta.com/help/artificial-intelligence/1436362127544482/ ）。
14. **记忆系统**：MEMORY.md、Soul.md（核心信念/边界/人格）、Identity.md（名字/形象/标语）均为可编辑文件；可用 forget skill 让 Muse 遗忘特定人/话题；**支持从其他 AI 助手导入 .zip 历史**（https://www.meta.com/help/artificial-intelligence/2225571704857152/ ；https://www.meta.com/help/artificial-intelligence/995796179982326/ ）。
15. **权限粒度**：Connectors 可设「Ask for some actions / Always ask」；Web access defaults 同理；Allowed websites 可撤销；审批选项为 Allow once / Allow for this task / Allow for this site / Always allow / Deny（https://www.meta.com/help/artificial-intelligence/1385290430137537/ ）。
16. **审计/可见性**：Activity log 记录动作与已授权项；assistant avatar 显示实时状态；可 See task details；System Files 提供更深层活动（https://www.meta.com/help/artificial-intelligence/1385290430137537/ ；https://www.meta.com/help/artificial-intelligence/2797651547267109 ）。
17. **语音与化身**：Connect 2026 公布实时语音对话、按描述定制声音、Muse Realtime Avatar（https://www.meta.com/blog/meta-connect-2026-everything-we-announced/ ）。
18. **自身邮箱地址**：Muse 将有独立邮箱，可代你收发/作为通信入口（同上，2026-09-23 公布）。
19. **AI 打电话（实验）**：可代你给公开电话的商家打电话（如问营业时间/预订），非用户可申请不接受此类来电（https://www.meta.com/help/artificial-intelligence/4532990443643263/ ）。
20. **多模态输入**：交互可包含文本、语音、照片；可从其他 app 分享进 Muse（https://muse.ai/privacy ；https://www.meta.com/help/artificial-intelligence/2225571704857152/ ）。
21. **子 agent/自定义工具/自改**：安全博客称 Muse 会「launches swarms of subagents, builds its own tools, and edits itself」，并在 VM 内编译代码、开发自定义 skill、处理并发 subagent 与 cron（https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse ）。

> 注：第 21 条为**官方博客自述**（marketing/engineering narrative），UI 文档层面未见「命名 Bot 花名册/群聊」等对等交互，只能算**产品能力宣称**，非可验证 UI 行为。

## 3. xAI Grok Bot：能力清单（15+，附一手证据）

1. **命名 Bot**：Bot = 持久、命名、有岗位/记忆/上下文的 agent，建议按角色拆分（Talent Scout、Expense Manager…）（https://docs.x.ai/grok-bot/bots ）。
2. **专属云电脑**：每个 Bot 有持久云电脑（浏览器+文件系统+终端），任务在「你的真实工具里」完成而非聊天草稿；关掉笔记本不停（https://docs.x.ai/grok-bot/overview ）。
3. **账号级共享电脑**：同一账号所有 Bot **共用一台**电脑——浏览器 cookie/登录态、文件、命令行凭据全共享；「Bot 之间不是安全边界」，需要独立环境请开独立 Cursor 用户（https://docs.x.ai/grok-bot/computer-and-apps ；https://docs.x.ai/grok-bot/teams-and-enterprises ）。
4. **每用户 Firecracker microVM 隔离**：用户间硬件级隔离、各有内核/内存/虚拟设备；一台电脑一个用户（https://docs.x.ai/grok-bot/teams-and-enterprises ）。
5. **连接器即插件**：从 Connect apps 安装，浏览器授权；`@` 引用连接器、`/` 引用 skill；连接器账号级生效（不隔离到单 Bot）（https://docs.x.ai/grok-bot/computer-and-apps ）。
6. **Computer use 兜底**：无 API/MCP 的站点靠浏览器点击操作；网站可能封自动化/会话过期/要求真人，Bot 会把这类步骤交回给你（https://docs.x.ai/grok-bot/overview ）。
7. **X 只读 + 插件**：无需连 X 即可搜索/读取公开帖；DM/书签/主页时间线需加 X 插件并登录（https://docs.x.ai/grok-bot/computer-and-apps ）。
8. **Skills（可复用指令）+ Routines（调度/触发）**：skill 记录步骤/决策规则/期望输出/安全边界；routine 指定某个 Bot 何时跑（计划或事件）；**Teach a task** 演示录制最多 10 分钟、不录麦克风，生成草稿 skill（https://docs.x.ai/grok-bot/skills-routines-and-automations ）。
9. **Routine 限额**：每 Bot 最多 50 个 routine，每 routine 保留最近 20 条运行记录，调度最小间隔 5 分钟，删除不可撤销（https://docs.x.ai/grok-bot/skills-routines-and-automations ）。
10. **事件触发**：可由 Cursor 账号集成（Slack 消息、GitHub 通知等）启动 routine，与 Slack/GitHub 插件相互独立（https://docs.x.ai/grok-bot/skills-routines-and-automations ）。
11. **Bot 间协作**：Bot 可异步互相发消息、对方被唤醒处理并稍后回复；可见交接（handoff）（https://docs.x.ai/grok-bot/chat-and-collaboration ）。
12. **群聊**：2–6 个 Bot 建群，共享一个结果并显式交接；`@` 点名、Reply 定向、群可编辑成员；群内不出现审批/密钥/邮件草稿卡（https://docs.x.ai/grok-bot/chat-and-collaboration ）。
13. **记忆模型**：稳定偏好、角色上下文、既往工作摘要；**会话与学习上下文按 Bot 独立**，共享文件/浏览器会话/直接交接可跨 Bot 传递；关键决策要求「查当前来源」而非记忆（https://docs.x.ai/grok-bot/overview ）。
14. **审批**：Allow once / Always allow（可存规则）/ Deny；未在场启动的工作（routine/事件/他 Bot）审批约 10 分钟后过期且不执行（https://docs.x.ai/grok-bot/approvals-security-and-privacy ）。
15. **Auto Review（独立审查模型）**：在动作执行前评估 shell、插件调用、computer use、自动化写入、委派（Cloud Agent/subagent）；可放行/要求审批/拒绝；**不覆盖记忆写入与多数设置改动**（https://docs.x.ai/grok-bot/security ）。
16. **本地执行策略**：Settings→General→Bot→Execution on Local Computer：Ask every time（默认）/ Always allow / Never allow；团队管理员可设更严上限（https://docs.x.ai/grok-bot/approvals-security-and-privacy ）。
17. **密钥移交**：密码/2FA/CAPTCHA/支付由你接管电脑完成；支持 secure secret request（值被掩码、不进 transcript、不给模型）；硬件安全钥匙可代用（macOS/Windows，Linux 不支持）（https://docs.x.ai/grok-bot/approvals-security-and-privacy ）。
18. **文件与产物**：桌面composer 最多 6 个附件；文档/图/音频 ≤25MB，视频 ≤200MB；支持图片、音视频、PDF、Office、CSV/JSON/YAML、代码、HTML/邮件、Jupyter；结果以卡片预览（https://docs.x.ai/grok-bot/files-and-results ）。
19. **移动端**：iPhone（iOS 18+）/iPad（iPadOS 18+）/Android 9+；与桌面同一后台、同一额度；iOS 分享表可投递图片/文件/链接/文本，Android 目前只支持文本（https://docs.x.ai/grok-bot/mobile ）。
20. **语音**：桌面 `Cmd/Ctrl+D` 听写、voice chat、Bot 可回 voice memo（可读 transcript）（https://docs.x.ai/grok-bot/chat-and-collaboration ）。
21. **X 标签 @bot**：在 X 帖/回复 @bot，主 Bot 接单，@bot 只在 X 回确认；需要 Grok 账号连上 X。**区域限制**：AU/UK/EU/冰岛/列支敦士登/挪威不可用（https://docs.x.ai/grok-bot/tag-on-x ）。
22. **Bot 模板分享/团队 Bot**：可生成模板链接（Public/Team-only），受管/企业账号默认 Team-only（https://docs.x.ai/grok-bot/bots ）。
23. **企业控件（多数 Enterprise-only）**：Network Controls（4 种模式，含域名/IP 允许列表）、Team Secrets、Team Setup（安装脚本清单）、Action Recording（90 天留存）、OpenTelemetry 导出（含可选对话内容导出）、SCIM、Enforce Auto-review 与团队规则（https://docs.x.ai/grok-bot/security ；https://docs.x.ai/grok-bot/teams-and-enterprises ）。
24. **审计与计费**：Audit logs（Enterprise，涵盖 Bot 创建/访问变更/Team Setup/routine 等控制面事件，可流式到 SIEM）；用量按产品在 dashboard 拆分（https://docs.x.ai/grok-bot/security-faq ）。

## 4. 消费者旅程对比

### 4.1 Muse
1. 用 Meta 账号登录（可 FB/IG/邮箱/手机号创建）→ Chat tab 直接对话（非回合制）。
2. 给任务 → Muse 澄清 → 后台执行 → 你在对话里看结果、要求修改。
3. 需要连接器时 Settings→Connectors 授权；写动作按权限设置弹审批。
4. Mac 上额外授予 Full Disk Access/Automation；本地 app 逐个选 Off/Read only/Read and interact。
5. 记忆/人格可在 Identity（MEMORY.md/Soul.md/Identity.md）里直接编辑，或用 forget。
6. 免费额度用尽 → Power $20/月 或 Max $100/月，或等下一周刷新。

### 4.2 Grok Bot
1. 安装桌面 app（macOS/Windows/Linux）→ 用 Cursor 账号登录（或链接 SuperGrok）。
2. 首次引导介绍 Bot/共享电脑/routine，并问「你常用哪些工具」（只影响推荐，不会自动连接任何工具）。
3. New→创建 Bot，写名字/岗位/工作方式 → 在 composer 发任务。
4. Bot 遇到登录 → 打开 Agent Computer→Take over 完成 2FA/CAPTCHA → 交还控制。
5. 结果可读后让其「保存为 skill」，稳定后建 routine（确认时区/输入源/审批边界）。
6. 额度随 Cursor 计划/SuperGrok 授权，周度刷新，超额走 on-demand（可设月上限）。

## 5. 计费与可用性（含营销 vs 可验证）

### 5.1 计费
- **Muse**：免费含用量上限；Power **$20/月 500M Muse tokens/周**，Max **$100/月 3B Muse tokens/周**；订阅随月自动续费（https://www.meta.com/help/subscriptions/1021145227643680/ ）。**可验证**（官方 Help Center）。
- **Grok Bot**：**不单独售卖**。含于任意付费 Cursor 个人计划与 Cursor Teams；也可链接 SuperGrok / SuperGrok Plus / SuperGrok Heavy / X Premium+，或自服务 Grok Business 席位。**周度用量**用尽后按需（on-demand）继续并计入月度上限；trial 是「用量信用」而非固定天数（https://cursor.com/help/grok-bot/plans ；https://docs.x.ai/grok-bot/teams-and-enterprises ）。**可验证**。
- 第三方 grok-bots.com 给出 SuperGrok Heavy $300/月、Cursor Ultra $200/月、Cursor Teams Premium $120/用户/月等具体价，官方未在此页逐项确认 → **标为二手/待确认**。

### 5.2 可用性
- **Muse**：「app 与网站尚未在所有地区可用，且部分功能地区性缺失」（https://www.meta.com/help/artificial-intelligence/1303670544995562/ ）；订阅需所在国可用 + 18 岁或法定成年（https://www.meta.com/help/subscriptions/1021145227643680/ ）。第三方称「2026-09-30 仅美/加」（usecarly/aiagentslibrary）→ **二手**。

## 6. 与我们 omp-bot README 基线的差异（重点 gap）

omp-bot 现状（摘自 README）：纯 Node 编排层，每 bot 一个 `omp --mode rpc` 子进程，**本地 cwd、本地会话续接、单写者数据目录、GUI 只听 127.0.0.1 且无鉴权、记忆后端被有意关闭、IM 桥未含**；群聊靠 relay 回合引擎，bot→bot 用同步 host tool `message_bot`（hop 上限 6、busy 拒绝）。相对两大竞品的结构性差异：

1. **运行时形态**：竞品是「云端持久电脑」（Muse VM / Grok Bot 云 VM，浏览器+终端+文件系统，关电脑也跑）；omp-bot 是「本机子进程 + 本机文件」，无云端常驻、无托管沙箱、无跨设备续跑。
2. **计算机使用的产品化层**：底层 OMP runtime 本身**已有** read/bash/edit/eval/task/web_search/write，并能经 eval 驱动浏览器、加载已装 skills/plugins——并非「完全无浏览器/工具能力」。真实差距在**产品托管层**：竞品有一等 browser/computer use 的**可视化接管**（观察、暂停、交还登录）、artifact 卡片与运行记录；omp-bot 这些要用户自己经 eval/host tool 拼装，无可视化接管 UI。
3. **连接器生态**：竞品有 OAuth 连接器市场 + 平台层 token 隔离（Cursor 后端 / Muse Secure Credentials Store）；omp-bot **无产品托管的连接器授权/授予层**（用户自行配置、无统一 grant/审计），而非「无工具」。skill 同理：OMP 有 skills/plugins，但无产品级 skill 库与启用管理。
4. **记忆**：竞品默认开启文件式/角色式长期记忆并可导出/遗忘；omp-bot **主动关闭**记忆后端，仅靠 `--continue` 会话续接（隔离故意为之，但与「团队型 agent」预期相反）。
5. **主动性**：竞品有 routine/调度、事件触发、主动 check-in、AI 打电话；omp-bot 无调度器，只能被动等消息。
6. **多智能体交互带宽**：omp-bot 只有同步 `message_bot`（易 busy/深度限制）；竞品支持异步交接、群聊 2–6、任务所有权移交、并行。
7. **权限/自治梯度**：竞品有独立审查模型（Auto Review / Sentinel）+ 多档审批 + 网络出口策略 + 本地执行策略；omp-bot 无审批层、GUI 无鉴权。
8. **触达面**：竞品覆盖手机/眼镜/WhatsApp/X 标签/自身邮箱；omp-bot 只有本机 GUI+CLI，IM 桥未实现。
9. **可观测/治理**：竞品有 Activity log、Audit logs、Action Recording、OpenTelemetry；omp-bot 只有进程内 `usage` 汇总与 debug 帧。
10. **计费/限额**：竞品有周额度 + 超额 + 分档；omp-bot 直接用用户本机 OMP 凭据，无产品级额度/成本闸门。

## 7. 优先级建议与验收标准（供上层决策，不含实现）

按「投入产出 + 与竞品差距最大」排序：

**P0 常驻与主动性（补最大缺口）**
- 建议：为 bot 增加调度（cron/事件）与后台回合，进程存活期外可续跑（哪怕先做本机 daemon）。
- 验收：给定「每天 8:00 跑 X」，在无人交互下触发并记录一次可审计运行；失败可重试且带 no-data 策略。

**P0 审批与自治梯度**
- 建议：引入独立审批层（逐动作 allow once/always/deny + 规则），并把 GUI 加上鉴权/绑定校验。
- 验收：高风险动作（外发消息/删除/支付）默认拦截并生成审批卡片；规则可收紧不可放宽；审批有超时语义。

**P1 记忆策略重审**
- 建议：把「关闭记忆」改成可选 profile（默认隔离、按 bot 可开），并提供查看/编辑/遗忘入口。
- 验收：可导出某 bot 的记忆文件；`forget` 能按主题清理且不污染其他 bot。

**P1 本地 computer use / 浏览器接管**
- 建议：至少提供「观察 + 接管」UI 与本地执行策略（Ask every time/Always/Never）。
- 验收：Bot 请求登录时用户可接管完成 2FA 并交还；本地命令默认逐条审批。

**P1 异步 bot→bot 交接**
- 建议：在现有同步 `message_bot` 外增加异步投递队列（收件箱 + 唤醒），保留 hop 防护。
- 验收：A 发起、B 稍后回复，A 不阻塞；深度/循环仍受上限；失败有回执。

**P2 触达面**
- 建议：实现一个 IM adapter（Telegram/飞书）把消息映射到 `chatWithBot`/`postToRoom`。
- 验收：IM 里私聊/群聊可用，回复能回到 IM，权限与 GUI 一致。

**P2 可观测**
- 建议：结构化动作日志 + 运行历史（对齐 routine run records 概念）。
- 验收：可按 bot/时间查动作与授权，能导出。

**P2 额度/成本闸门**
- 建议：在编排层加每 bot/每日 cost 上限与超额策略（对齐竞品周额度思路）。
- 验收：超限时按策略拒绝或转审批，并有用量报表。
