# 独立复核与主代理裁决

复核对象为本次对标调研和实施方案。两个独立 reviewer 上下文使用本次会话指定的 DeepSeek V4.1 Flash。不是不同模型共识，也不是代码实现验收。

## 证据复核

EvidenceVerdict 交叉检查十余条官方来源及本地源码。主报告四家身份区分、66 条差距的主要结论、HTTP 探针与浏览器攻击链的区分、超时机制与未复现并发的区分均与证据一致。

提出两处 Dots 分报告错误，主代理已修正。

- 移动创建有官方来源冲突。当前 learn.chatgpt.com/docs/dots.md 明确可在移动 App 创建，Help 20001530 仍称不能。改成双源冲突，未实操裁定。
- 短信 coming soon 与美国 Pro 有限 beta 的说法混用。按来源分别标注当前帮助页 beta 与部分文案更新不同步，不再用统一将来态下结论。

主代理另修正本地核心分报告把可能并行回合写得过强、Relay mentionBudget 被误写为共享的两处问题。OpenMausBot 分报告修正本项目桌面包已含 OMP、实际群上限为 12 而非未使用的 3、未经共同实验不得宣称防死锁优于竞品。核心差距排序未改变。

## 方案复核

PlanVerdict 提出七项实质设计问题。主代理阅读 OMP approval-mode 与 RPC 文档后，将具体约束补入实施方案。

| 问题 | 已采取的方案修正 |
|---|---|
| 只中止 OMP，宿主 handler 仍可继续 | host_tool_cancel.targetId 关联 AbortController，覆盖宿主工具、连接器与子任务；外部效果未知进入对账，不假称停止 |
| runtime 只按 botId::scope 复用，会沿用宽权限 | 环境、范围与 capability 版本兼容检查；先宽后窄必须重建或验证热更新；旧会话不恢复旧批准 |
| rpc --no-ui 不能接原生审批卡 | 明确受控 host tool 用宿主审批；原生工具路径使用 plain rpc-ui 去掉 --no-ui，未通过门控不开放 |
| 本机完全能力无法保证拒绝后任意代码不绕过 | 将不可绕过验收限定受控与沙箱模式；本机模式明确安全降级，默认不运行无人值守写 |
| --no-tools 与使用内置 read 的方案矛盾 | 调研用宿主限定读取与公开请求，数据与开发用沙箱工具，图像单独验协议 |
| 同步嵌套委派入队可能 A→B→A 死锁 | 用户侧有界排队，嵌套委派保持 busy 拒绝，待异步 inbox cutover |
| 忽略已有 OMP 预算入口 | 表中补 goal.token_budget 和 --max-time，标未测和 RPC continuationModes 限制，不替代整体费用账本 |

这些是已完成的文档修正，不是已实现的运行保证。实际审批桥接、宿主工具停止、Windows 沙箱、预算和故障恢复仍是实施阶段的硬验收项。
