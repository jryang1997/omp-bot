# 0001 绑定电脑只加客机工具，不拿走本机工具

- 状态：已采纳，2026-10-16
- 推翻：`.scratch/bot-computers/spec.md` 完成条件 2 的后半句，"电脑模式实际工具清单中没有本机 bash/read/eval、浏览器、任意用户 MCP 等绕过通道"
- 来源：`.scratch/team-architecture/map.md` 的 D1、D3，落地在 `.scratch/team-rebuild/issues/06-additive-computer.md`

## 背景

0.1.x 里每个 bot 绑定一台自己的 Linux 虚拟机。为了让模型"只能"在客机里干活，绑定电脑的回合启动 omp 时加 `--no-tools --no-extensions --no-skills`，overlay 关掉项目和用户 MCP，运行时还校验工具清单里只剩客机工具。

用起来的结果是 bot 一绑定电脑就变弱：读写本机文件、跑本机命令、技能、扩展和 MCP 全没了，原本在本机能做的事反而做不了。这条限制挡的是模型绕过客机直接动宿主，但 omp 自己的审批档已经管着本机工具，隔离再叠一层只换来能力损失。

## 决定

- bot 是住在 Windows 本机的 omp agent。绑定电脑只是在本机能力之上加客机工具（截图、输入、命令、文件、发布成果、装系统包）。
- 绑定电脑的回合不再加 `--no-tools`、`--no-extensions`、`--no-skills`，overlay 不因绑定电脑关 MCP。运行时的电脑档工具面校验删掉，披露文案改成本机和共享电脑两套工具都在。
- 本机工具照常走审批档：只聊天不给工具，本机改东西先问我，全部放手不问。客机工具在两种可执行档里都 allow，只有装系统包每次都问（omp 在任何审批档下都尊重用户级的 prompt）。
- 跨 bot 的边界保留：模型不能选别的 bot 的座席，客机工具的电脑 id 由服务端持有。完成条件 2 的前半句不变。

## 后果

- 绑定电脑的 bot 和没绑定的一样能用本机工具、技能、扩展和 MCP，另外多一台共享 Linux 电脑。
- "电脑模式下模型碰不到宿主"不再成立。全部放手档的 bot 本来就能访问整个本机账户，这里如实披露，不再用工具清单假装隔离。
- 共享电脑里的隔离只防误操作：每个座席一个 Linux 用户，主目录 0700，没有 sudo。宿主侧不做强制隔离（见 spec 的 Out of Scope）。
- `computer_host_escape_denied` 委派边界一起删掉：绑定电脑的 bot 自己就有本机工具，这条边界没有意义。`POLICY_VERSION` 升到 3，旧进程不会被复用。

## 不要改回去的理由

如果以后想重新"电脑模式只给客机工具"，先回答这两个问题：bot 失去的本机能力由什么补上；审批档管不住的那部分风险具体是什么。只为了"看起来更隔离"而收窄，会回到 0.1.x 绑定电脑就变弱的老问题。
